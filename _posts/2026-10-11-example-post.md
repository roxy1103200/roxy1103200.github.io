# 今天改造 Agent 工作流的一点心得

今天我把注意力从“让模型答得更聪明”转向了“让整条流程更可靠”。我在理解阶段前加入了规则预检和槽位检查，减少信息不全时的无效调用；增加脱敏槽位摘要，方便按缺失字段定位问题；再用确定性规则检查结果，并保留 ReAct 的步数、工具调用和模型预算上限。

这次用 168 道题、A/B 各运行两轮，共完成 672 次真实任务。与上一轮共同的 144 道题相比，任务成功率从 88.2% 提升到 96.5%，工具链正确率从 88.9% 提升到 96.5%，口语题成功率从 77.1% 提升到 94.4%。平均模型调用下降约 44%，已观测 Token 下降约 36%。这些结果让我更确定：先把可确定的判断交给规则，把模型调用留给需要理解和组合推理的部分，能同时改善准确性和开销。

我也看到不能只看整体平均数。标准题成功率从 99.3% 略降到 98.6%；口语组合题的事实验收率从 95.8% 降到 91.7%；新增澄清补问题的工具链通过率是 79.2%。测试还定位出几类具体问题：口语里的“还有 39 号场”漏识别场次号，退票问题里的“多少分钟”被误当成影片时长，补充日期时有些请求没有继承之前的排期范围。接下来应围绕这些可复现的问题修规则和任务续接逻辑。

GLM 这轮实际调用了 14 次，7 次超时、7 次限流，没有一次成功接管理解。因此我不能把整体提升算作 GLM 带来的收益；它当前的等待和回退行为还需要优化，也需要补充限流原因的细节记录。评测中没有发生重复工具执行或预算越界，有一次任务因停滞触发熔断后退出。这说明硬限制在本轮覆盖的任务里起到了兜底作用，但后续还应继续用失败路径验证边界行为。

这次改造让我对 Agent 的认识更具体了：可靠性来自清晰的任务拆解、对缺失信息的处理、对工具结果的核验，以及明确的退出条件。Reflection 可以帮助检查遗漏，却不能替代独立验收；最终还是要靠固定题集、可追溯的调用记录和分项指标判断流程是否真的变好。
